# Week 02 — Your repo passes the check, then: predict, break, fix

## 1. What is this file?

This README explains how to run the Python examples in `Week02`. The examples explore how rules, randomness, and tidal-current data can become drawings. They also include exercises in checking whether a program produces the intended result.

| File or folder | Purpose |
| --- | --- |
| `schotter.py` | An interactive grid of squares that becomes increasingly disordered. |
| `schotter3d.py` | A three-dimensional version made of cubes, with an adjustable camera. |
| `nake.py` | A grid of vertical and horizontal lines generated by a set of rules. |
| `spec/` | Three candidate implementations and a viewer for comparing them against `BRIEF.md`. |
| `faults/` | Four debugging exercises with deliberately incorrect results. |
| `tides/fetch_tides.py` | Retrieves tidal-current forecasts, caches the responses, and writes a CSV file. |
| `tides/tides.py` | Turns the current speeds and directions in `tides.csv` into a drawing of distorted rings. |

The graphical examples declare a requirement for Python 3.10–3.13 and the `pygame-ce` package. The data-fetching script requires Python 3.10 or later and `requests`. The candidate scripts and the first three debugging exercises use only Python's standard library.

## 2. How do I run it?

The commands below use `uv`, which must be installed and available in your terminal. Scripts with a `# /// script` block declare their Python and package requirements there. Running them with `uv run` uses those requirements; the first run may need an internet connection to download dependencies.

### Start in the correct folder

Open a terminal in the `Schotter` project folder, then run:

```powershell
cd .\Week02
```

If the terminal is already in `Week02`, skip this step. `cd` changes the terminal's working directory. Opening a file in VS Code does not automatically move the terminal to that file's folder.

### Run the interactive drawings

From `Week02`, run one of these commands:

```powershell
uv run schotter.py
uv run schotter3d.py
uv run nake.py
```

Each command opens a drawing window. Close that window before running the next example in the same terminal.

| Script | Controls |
| --- | --- |
| `schotter.py` | **Space** selects a new seed; **Left/Right** changes the seed by one; **Up/Down** increases or decreases disorder; **R** resets the parameters. |
| `schotter3d.py` | Drag with the left mouse button or use the **arrow keys** to orbit; **+ / -** moves the camera closer or farther away; **Space** selects a new seed; **[ / ]** decreases or increases disorder; **W** toggles wireframe mode; **R** resets the seed, disorder, and camera. |
| `nake.py` | **Space** selects a new seed; **Left** lowers the threshold, allowing more horizontal caps; **Right** raises it, allowing fewer; **R** resets the parameters. |

In all three windows, press **S** to save a PNG or **Q / Esc** to quit.

To save a drawing without opening a window, supply an output filename:

```powershell
uv run schotter.py --save schotter-preview.png
```

The same `--save filename.png` option is available in `schotter3d.py`, `nake.py`, `spec/compare.py`, and `tides/tides.py`.

### Compare the candidates

Starting in `Week02`:

```powershell
cd .\spec
uv run compare.py
```

Read `BRIEF.md` for the requirements. The viewer displays all three candidates against a faint reference grid. Press **Space** to generate them again, **S** to save `compare.png`, or **Q / Esc** to quit.

You can also generate an individual SVG:

```powershell
uv run candidate_a.py
```

Replace `a` with `b` or `c` to run another candidate. Open the resulting SVG in a browser.

Return to `Week02` when finished:

```powershell
cd ..
```

### Run the debugging exercises

Starting in `Week02`:

```powershell
cd .\faults
uv run 01_average.py
uv run 02_grid.py
uv run 03_ramp.py
uv run 04_nake.py
cd ..
```

The first three scripts print their results in the terminal. The fourth saves `04_nake.png` in `faults`; open the image to inspect it. These exercises intentionally contain mistakes. Compare each result with the specification at the top of its script.

### Draw the tidal currents

Starting in `Week02`:

```powershell
cd .\tides
uv run tides.py
```

An existing `tides.csv` is included in this folder, so fetching data is optional. The drawing script writes `tides.svg` and then opens an interactive window.

- **Space:** choose a new orientation value, changing the shape of the rings.
- **Left/Right:** decrease or increase displacement.
- **[ / ]:** decrease or increase the number of rings.
- **R:** restore the initial settings.
- **S:** save the current window as `tides.png`.
- **Q / Esc:** quit.

To fetch data for the date and time configured in `fetch_tides.py`, run:

```powershell
uv run fetch_tides.py
uv run tides.py
```

To request data starting from the current quarter-hour instead:

```powershell
uv run fetch_tides.py --now
```

`--now` uses your computer's local clock. For Hong Kong local times, use a computer clock set to that time zone. Uncached requests require an internet connection and an available data service.

### Where are the output files saved?

Most PNG exports, `--save` paths, and candidate SVG files are saved relative to the terminal's working directory. With the commands above, they appear in the folder from which you ran the script.

The tidal scripts always read or write `tides.csv`, `tides.svg`, and `cache/` beside the scripts. The fourth debugging exercise always writes its PNG into `faults`.

Saving to an existing filename replaces that file. Fetching data rewrites `tides.csv` with the available results, which may cover fewer time slots if some requests fail. If no rows are collected, the existing CSV is left unchanged.

## 3. What does the script do?

### Schotter: from order to disorder

`schotter.py` creates a grid of squares. Each square receives a random rotation and horizontal and vertical displacement. The range of those changes grows with the row number:

```python
damage = chaos * (row / ROWS) ** 2
```

The first row has no displacement or rotation. The squared term keeps the upper rows relatively calm and increases disorder more quickly toward the bottom.

The main parameters are `COLS`, `ROWS`, `SEED`, `CHAOS`, and `SQUARE`. Keeping the seed and other settings unchanged reproduces the same arrangement.

`schotter3d.py` applies the same idea to cubes. It rotates and displaces them in three dimensions, then projects their corners onto the screen. The camera controls change the view of the arrangement.

### Nake: lines governed by rules

`nake.py` visits the grid column by column. Each cell can contain a vertical bar, a horizontal cap, both, or neither.

Bars become more likely near the diagonal. A cap is allowed only when the previously visited cell was empty. The `H_PROB` parameter controls the cap threshold: lower values make caps more likely when that condition is met.

Change `SIZE`, `SEED`, `H_PROB`, or `CELL` near the top of the file to experiment with the pattern.

### Specification and debugging exercises

The scripts in `spec/` demonstrate why a drawing that looks plausible may still fail its requirements. Use `compare.py` and `BRIEF.md` to inspect the candidates' initial alignment, growth of disorder, repeatability, and displacement limits.

The scripts in `faults/` apply the same idea to smaller problems: calculating an average, building a grid, generating a sequence, and drawing a raster. Running without an error does not guarantee a correct result.

### Tidal currents: from data to rings

`fetch_tides.py` requests forecast data for a sequence of time slots. It reuses existing cached responses and saves new responses in `cache/`. It extracts the timestamp, point ID, current speed in knots, direction in degrees, longitude, and latitude into `tides.csv`.

The default settings request 24 time slots at 15-minute intervals, starting at 14:00 on 10 September 2026. Adjust `DATE`, `TIME`, `SLOTS`, `STEP_MINUTES`, and `MODE` to change the request.

`tides.py` groups the CSV rows by time and sorts the current measurements by point ID. Each ring begins as a circle whose vertices are displaced using the current speeds and directions. Earlier time slots appear as smaller inner rings; later slots appear farther out. Line thickness depends on the mean speed of the selected measurements.

| Parameter | Default | Purpose |
| --- | --- | --- |
| `RINGS` | `24` | Initial number of rings, limited to the available time slots. |
| `RESOLUTION` | `200` | Number of vertices in each ring. |
| `DISPLACEMENT` | `25.0` | Strength of the displacement caused by the currents. |
| `LINE_WIDTH` | `1.5` | Multiplier for speed-based line thickness. |
| `ORIENTATION` | `0.70` | Controls vertical scaling and horizontal displacement. |
| `CENTRE_VOID` | `0.0` | Increases the open space at the centre when raised. |
| `SPREAD` | `False` | Selects measurements from the start of the sorted data; `True` samples across the full list. |

If you increase the ring count beyond the number of time slots, the script reuses the data cyclically.

`tides.svg` records the initial drawing each time the script runs. Interactive adjustments change the window only; press **S** to capture the adjusted drawing as a PNG. SVG files can be opened in a browser and remain sharp when enlarged.
